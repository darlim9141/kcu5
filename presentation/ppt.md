## 1. 중간평가 기점 주요 변환점

### 중간평가 이전 (슬라이드)

**기존에 계획했던 핵심 기능**

- 사용자가 전신 사진을 업로드하면 4가지 스타일을 기준으로 분석, 어느 스타일에 가장 가까운지 판단해준다

**진행사항 (중간발표 이전까지)**

- 데이터 수집(스타일 별 사진) 및 머신러닝 학습 진행 (정확도 약 60%)

- Figma 활용해서 프론트앤드 기본적인 디자인 구상

**중간발표 당시 주요 피드백**

- 정확도 개선 필요

- 아메카지 스타일 분석 정확도 매우 낮음

### 중간평가 이후 (슬라이드)

#### A. 개선점

- 아메카지 스타일의 복잡성을 고려해서 해당 스타일을 "클래식"으로 변경 -> (캐주얼, 미니멀, 스트릿, 클래식)

- 사진 데이터모델 추가 확보 (각 스타일에 맞는 사진 추가로 확보)

- 함수 수정을 통해 Outlier 변수 처리

- 결과: 정확도 약 80%

#### B. 기능 추가

- 다중 이미지 업로드 시 평균/최다 스타일 통계 제공 (이를 통해 사용자의 종합적인 스타일 방향성을 분석)

- 사용자가 올린 사진을 갤러리에 저장하여, 데이터가 정리되는 기능

- 우리가 가진 학습 데이터를 3D 공간에 시각화하고, 사용자가 업로드한 이미지도 같은 방식으로 좌표를 계산해서 그 3D 공간 속에 표시하는 기능

### 협업과정 (새로운 슬라이드 추가 필요!)
- Version Control (깃 디렉토리 사진)
- 미팅+커밋 기록 (미팅날짜 기록된 캘린더 사진, 깃 Contributors 사진)
- 바베큐 사진


## 2. 시연 (순서)

- 화면 들어갔을 때 기본적인 레이아웃 설명 ('여기 갤러리 화면에 이제 옷 스타일이 기록될거예요')

- 실제로 사진 첨부하는 장면 시연

- 사진 첨부, 분석, 결과 도출하는 그 시간 사이에 백엔드 계층 설명, FastAPI관련 내용 설명, 프론트엔드 구성요소 (Vite, Typescript) 언급

- 사진 나오면 하단에 관련된 옷 사이트 나올거임. 그 사이트를 들어가는 장면까지 보여준다. (이 기능을 위해 어떤 기술이 사용되었는지에 대한 설명도 할 예정)

> 1. 기존에 이 프로젝트를 위해서 Gemini를 Fine Tuning(쉽게 말하자면 사전교육)을 진행함. 이를 통해 Prompt를 굳이 매번 길게 주지 않더라도 그 Fine Tuning되어 있는 Gemini가 알아서 이 프로젝트에 딱 적용 가능한 결과들을 도출해내도록 한다.
> 2. 모델이 분석한 스타일을 Fine Tuning된 Gemini에게 전달, 전달 받은 응답을 json 파일로 만들어서 frontend에 적용되는 방식

- 3D 그래프 설명 (이 기능의 목적 + kmeans 언급)

- 다시 갤러리 화면으로 돌아와서 갤러리에 사진이랑 날짜 추가된거

- 사진 하나 더 첨부하기 (전과 다른 스타일 옷으로) + 이거 로딩되고 결과 나오는 동안 궁극적으로 이 어플이 무슨 목적을 갖고 있는지에 대해 설명하기

- 분석화면 간략하게 보여주고 다시 갤러리로 돌아와서, 사진 하나 더 추가된거 보여주기

- 통계 페이지 들어가서 어떤 식으로 나오는지 보여주기

  

## 백엔드/프론트엔드 구조 (슬라이드 필요없음)

- Git 디렉터리 구조 사진 (Git에서 캡처한 사진 첨부)

- 기술스택 (Git에서 캡처한 사진 첨부 + 추가/변경된 부분 반영)

- 프론트엔드 구성요소: Vite, TypeScript 사용

- Jupyter Notebook (일부 코드 정리된 화면)

### 백엔드 설명

#### A. 백엔드 계층 설명

- 백엔드 구조를 역할에 따라 크게 3가지 계층으로 분리하였다. 첫째는 API 계층으로써, 이는 프론트엔드에서 업로드한 사진을 서버로 보내고, 요청받은 형식을 검증하고, 이후에 백엔드를 통해 산출된 결과를 JSON 방식으로 다시 응답하는 역할을 의미한다. 두번째는 로직 계층으로, 실제로 이미지를 분석하고, 분류 모델을 호출하고, 3D 좌표를 계산하는 등 말 그대로 실질적인 이미지 처리와 AI 분석을 의미한다. 마지막으로는 리소스 계층으로, 백엔드가 시작될 때 준비되는 작업들을 담당한다.

#### B. FastAPI

- 특별히 API 계층을 위해서는 Fast API 사용했는데, 처음에는 Flask를 사용할 예정이었으나, Fast API가 비동기 기반을 통해 훨씬 빠르게 작업을 처리한다는 점과 모든 요청 및 응답을 자동으로 검증하는 기능을 갖고 있다는 점을 고려해서, 이를 사용하기로 결정했음.

#### C. kmeans, T-SNE

- 3D 좌표 계산 및 시각화는 기존에 사용했던 kmeans를 활용하였음
